> 本書は「既に決まっている判断」と「実装済みの事実」を構造化して書き起こしたもの。

---

## 1. 目的（WHY）

ジョブカンが出力する **確定シフトの xlsx（1人・1ヶ月分、前月16日〜当月15日締め）** を、
各スタッフ本人の Google カレンダーへ **一括で反映** する。

解決したい課題:

- 管理者が確定シフトを1人ずつ手で各人のカレンダーへ転記するコストをなくす。
- 手作業に伴う **転記ミス（別人の予定に書く・時間の写し間違い）** をなくす。

---

## 2. 利用者（WHO）

| 利用者 | 役割 |
| --- | --- |
| 社長（管理者） | xlsx を受け取り、取込を実行する。異常の最終確認者。 |
| 各スタッフ | 予定を受け取る側。自分の Google カレンダーへ確定シフトが反映される。 |

---

## 3. 入力（WHAT — 入力仕様）

ジョブカンの確定シフト xlsx。**1ファイル = 1人・1ヶ月分**。

| 項目 | 位置・書式 | 備考 |
| --- | --- | --- |
| ファイル名 | 例「氏名（A0187） 2026年08月度.xlsx」 | 対象年月とスタッフコードが含まれる |
| シート名 | 氏名 | staffName のフォールバック |
| 対象月ヘッダ | `rows[0][0]`（先頭セル） | "YYYY年M月" を先頭アンカーで読む |
| スタッフコード | 4行目（`rows[3]`）の col2 | 唯一の安定キー。書式外・空なら取込中止 |
| 氏名 | 4行目 col0 | 空ならシート名で補完 |
| 所属 | 4行目 col4 | 任意。分解せず1文字列で保持 |
| 実データ | "日付" ヘッダ行の次行以降（無ければ index9 以降） | 前月16日〜当月15日の締め |
| 日付セル | col0、"M/D" 形式 | 締め日ベースで年補完 |
| 出勤/退勤 | col5 / col6、"HH:MM" | 両方が勤務時刻の行だけ採用 |

**対象年月の決定順序**（[design.md](./design.md) 参照）:
1. ファイル名から導出した `targetMonth` を最優先で渡す（apps/web の本筋）。
2. 未指定時のみ、先頭セル `rows[0][0]` の "YYYY年M月" を読む。無ければ throw。

---

## 4. 安全要件（最重要・妥協不可）

この機能は **他人のカレンダーへ書き込む** ため、安全要件は妥協しない。

### 4.1 staffCode を唯一の安定キーにする

- **staffCode（英字1文字 + 数字4桁、例 A0187）が全社で唯一の安定キー。**
- **運用の突合は staffCode のみで行う。**
- **氏名照合は運用に使わない。** 氏名で突合すると別人の予定に書き込む事故リスクがある。
  氏名は初期登録時に人間が候補を確認するための表示補助にとどめる。

### 4.2 全面 fail-loud

- 推測して既定値を埋めない。特定できない入力は **throw して取込を中止** する。
- 対象年月が特定できない／月が範囲外／staffCode が書式外・空／
  ファイル名の staffCode とシート内 staffCode が不一致、はすべて fail-loud。

### 4.3 誤爆防止5層

書き込み事故を **構造で** 防ぐため、多層防御を敷く（[design.md](./design.md) に詳細）:

1. **既定 dry-run。** 明示的に apply しない限り書き込まない。
2. **`JOBCAN_APPLY_ENABLED` 未設定なら強制 dry-run。**（環境変数ガード）
3. **staffCode allowlist。** 許可されたスタッフのみ対象にする。
4. **書き込み関数は dry-run 分岐の内側にのみ置く。**（dry-run 時は I/O 自体を呼ばない）
5. **削除は自タグ限定。** `managedBy === "jobcan-sync"` かつ `shiftId` 一致のイベントのみ削除。
   無タグ・本人手動予定・他ツール予定は絶対に消さない。

### 4.4 一人の失敗を他人へ波及させない

- あるスタッフの解決失敗（未登録・未在籍・未連携・解決時例外）は、
  **その人をスキップして warning に積むだけ**。他人のカレンダー処理を止めない。
- reconcile は常に **その人自身の refreshToken と calendarId（= 本人 email）** でのみ呼ぶ。

---

## 5. 期待する振る舞い（正常系）

1. xlsx を（複数）アップロードする。
2. ファイル名から対象年月を導出し、シートをパースして確定シフトを抽出する。
3. staffCode ごとに束ね、staffCode → email → refreshToken を解決する。
4. 各人のカレンダーの当該期間の既存イベントを取得する。
5. **1人・1日単位で「あるべきコマ集合」と「既存の自タグ集合」を突合**し、
   作成すべきコマを作り、消えたコマの自タグを掃除する（日内 diff、[design.md](./design.md) 参照）。
6. dry-run なら計画のみ返す。apply なら実際に反映する。
7. 異常・スキップは warning として集約し、人間が気づけるよう通知する（Step 2-7 で Slack 通知に配線済み）。

---

## 6. 非目標（やらないこと）

| 項目 | 扱い | 理由 |
| --- | --- | --- |
| 深夜跨ぎ勤務 | 対応しない | 「深夜跨ぎは存在しない」前提（社長確定）。`end <= start` は異常として凍結（生成スキップ + 当日削除を全抑制 + warning） |
| 空日削除 | 既定オフ | 既定は「存在する日だけ反映・空日は放置」。`reconcileRemovals` オプションで任意に有効化できる |
| 除外行の件数・理由の返却 | 将来の UI で対応 | 取込フェーズ1では件数/理由を返さない（可視化は UI 実装時） |
